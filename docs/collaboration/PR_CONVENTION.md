# Pull Request 컨벤션

모든 코드 변경은 작업 브랜치에서 진행하고 Pull Request로 기준 브랜치에 반영한다. 기준 브랜치에 직접 커밋하거나 푸시하지 않는다. PR 생성과 병합은 사용자의 명시적 요청이 있을 때만 한다.

## 제목

변경 요약과 연결된 GitHub Issue 번호를 쓴다.

- `[#12] 대기실 참가자 목록 표시`
- `[#23] 재접속 상태 갱신 오류 수정`

## 본문

GitHub PR 작성 화면에 제공되는 `.github/pull_request_template.md`를 사용하고, 작업과 관련 없는 항목은 사유를 적어 정리한다.

- 변경 요약 및 주요 구현 내용
- 관련 이슈와 자동 종료 키워드(예: `Closes #12`)
- 수행한 검증 결과와 실행하지 못한 검증 및 이유
- 리뷰어가 확인할 사항 또는 알려진 한계
- 대안을 검토한 설계 변경이 있으면 관련 의사결정 문서 링크

검증하지 않은 항목을 통과한 것처럼 표시하지 않는다. CI가 경로 조건으로 생략된 경우에도 본문에 그 사실을 적는다.

## 병합

- PR을 기준 브랜치 대상으로 연다. 대상 브랜치가 불분명하면 확인한다.
- 리뷰·필수 CI·충돌 상태를 확인한 뒤 사용자의 병합 요청에 따라 GitHub PR을 통해서만 병합한다.
- 병합 전에는 연결 이슈를 닫지 않는다. PR의 `Closes #<번호>` 연결로 병합 시 자동 종료되도록 한다.
