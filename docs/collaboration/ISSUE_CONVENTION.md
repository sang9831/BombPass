# GitHub Issue 컨벤션

작업 추적에는 Jira 대신 GitHub Issues를 사용한다. 제목과 본문은 한국어로 작성하고, 한 이슈에는 완료 여부를 판단할 수 있는 한 가지 작업을 담는다.

## 제목

접두어와 구체적인 작업 설명을 쓴다.

- 기능: `[기능] 대기실에서 참가자 목록 표시`
- 버그: `[버그] 재접속 후 게임 상태가 갱신되지 않음`
- 작업·개선: `[작업] 프론트엔드 빌드 검증 추가`

## 본문

GitHub Issue 등록 시 제공되는 기능, 버그, 작업 템플릿 중 알맞은 것을 선택한다. 본문에는 해당되는 항목을 채운다.

- 배경과 해결할 문제
- 기대하는 동작 또는 구체적인 작업 범위
- 완료 조건(체크리스트로 작성)
- 재현 절차와 실제/기대 결과(버그인 경우)
- 관련 문서, 화면, 로그 등 필요한 참고 정보

요구사항 문서에서 정책이 미확정이면 확정된 동작처럼 기술하지 말고, 미결정 사항으로 표시한다. 비밀값, 인증 정보, 사용자 개인정보는 이슈에 올리지 않는다.

## 연결

- 기존 이슈가 작업과 일치하면 새 이슈를 중복 생성하지 말고 기존 이슈를 사용한다.
- 작업 브랜치에는 GitHub Issue 번호를 포함한다. 예: `feature/12-lobby-player-list`, `fix/23-reconnect-state`.
- 이슈 번호나 저장소의 기준 브랜치를 추측하지 않는다.
